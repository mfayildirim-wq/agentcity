# Agent Arena v2 – Umsetzungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Aus der v1-Beobachtung wird eine steuerbare Arbeitsumgebung: Agenten verschiedener Tools starten, mit ihnen chatten, Berechtigungen im Browser bestätigen, Besprechungen und Aufgaben, Verlauf in SQLite.

**Architecture:** Node-Server (ESM, keine Build-Stufe) mit Modulen `server/{core,agents,acp,pty,watchers,db,api}`; Browser-Frontend (Three.js, ohne Bundler) mit `public/js/{store,world,avatar,ui/*}`; Verbindung per WebSocket (`ws`); Agenten werden über das Agent Client Protocol (ACP, `@agentclientprotocol/sdk`) gesteuert, externe Sessions weiter per Dateibeobachtung.

**Tech Stack:** Node ≥ 22 (`node:sqlite`, `node:test`), `ws`, `node-pty`, `@agentclientprotocol/sdk`, Adapter `@agentclientprotocol/claude-agent-acp` und `@zed-industries/codex-acp`, Three.js, `@xterm/xterm` + `@xterm/addon-fit`. Alles bereits in `package.json` installiert.

**Spezifikation:** `docs/superpowers/specs/2026-10-07-arena-v2-design.md` – vor jeder Aufgabe lesen.

**Regeln für alle Aufgaben**
- Sprache in UI und Kommentaren: Deutsch; Bezeichner Englisch.
- Design kompakt und dezent (siehe v1-CSS); keine großen Titel, Icons statt Textknöpfe.
- Kein Build-Schritt: ESM direkt im Browser, Vendor-Dateien über `/vendor/<paket>/…` aus `node_modules` ausliefern.
- Tests mit `node --test test/`; vor jedem Commit `node --check` auf geänderte Dateien und `npm test`.
- Demo-Modus (`?demo`) muss nach jeder Aufgabe weiter funktionieren.
- Server nur auf 127.0.0.1; alle WS-Verbindungen brauchen das Token.
- Commit nach jeder Aufgabe; Commit-Nachricht endet mit `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## WebSocket-Protokoll (verbindlich für alle Aufgaben)

Alle Nachrichten sind JSON `{ "type": string, "id"?: string, ...payload }`. Antworten auf Anfragen tragen dieselbe `id` und `type: "<request>.result"` oder `type: "error"` mit `{ id, message }`.

Client → Server
```
hello                { token }
session.create       { toolId, cwd, mode?: 'confirm'|'auto', title? }          → session.create.result { agentId }   (mode = Arena-Modus)
session.prompt       { agentId, text, meetingId? }                             → session.prompt.result { ok }
session.cancel       { agentId }
session.adopt        { agentId }   (Watcher-Agent → steuerbar, via loadSession) → session.adopt.result { agentId }
session.close        { agentId }
session.setMode      { agentId, modeId }        (Modus des Tools, ACP session/set_mode)
session.setArenaMode { agentId, arenaMode: 'confirm'|'auto' }   (Arena: Rückfragen bestätigen bzw. automatisch freigeben; nur dieser steuert die Auto-Freigabe)
permission.answer    { permissionId, optionId }   (optionId 'cancel' = Abbruch)
pty.open             { agentId, cols?, rows? }                                 → pty.open.result { ptyId, buffer, reused }
                     (Nutzer-Shell `$SHELL -l` im cwd; nur steuerbare Hauptagenten; eine je Agent – erneuter Aufruf liefert dieselbe
                     Shell samt Ringpuffer (64 KB) zur Wiederanzeige)
pty.input            { ptyId, data }          (nur Nutzer-Shells; Agenten-Terminals sind schreibgeschützt)
pty.resize           { ptyId, cols, rows }    (nur Nutzer-Shells)
pty.close            { ptyId }                (nur Nutzer-Shells)
pty.list             { agentId }                                               → pty.list.result { terminals[] }
                     (alle Terminals des Agenten inkl. Subagenten, älteste zuerst: { ptyId, agentId, ownerId, kind: 'user'|'agent'|'display',
                     command, args, cwd, t, exited, exitCode, signal, released, data } – data = Ringpuffer; Browser lädt die Liste beim
                     Öffnen des Reiters „Terminalausgaben“)
task.create          { title, description?, meetingId?, sourceMessageId?, assigneeId? }   → task.create.result { task }
                     (assigneeId: gleich zuweisen; schlägt das fehl, bleibt die Aufgabe offen angelegt und es kommt ein Fehler)
task.update          { taskId, status?, title?, description? }                  → task.update.result { task }
task.assign          { taskId, agentId }      (schickt Aufgabe als Prompt)      → task.assign.result { task }
task.delete          { taskId }                                                → task.delete.result { ok }   (+ Broadcast task.remove)
                     Task { id, title, description, status: open|active|waiting|done, assigneeId, meetingId, sourceMessageId,
                     createdAt, updatedAt }. Die zuletzt zugewiesene Aufgabe eines Agenten folgt seinem Status (thinking/tool →
                     active; waiting_permission/waiting_user/error → waiting; Session beendet → waiting); Züge aus einer Besprechung
                     (Prompt mit meetingId) ändern den Aufgabenstatus nicht. Neue Zuweisung an denselben Agenten: die bisherige aktive
                     Aufgabe → waiting; Neu-Zuweisung X→Y: X folgt der Aufgabe nicht mehr. done/open nur durch den Nutzer.
                     Nur steuerbare Hauptagenten (source 'acp', kind 'main') sind Bearbeiter bzw. Teilnehmer.
meeting.create       { title?, participantIds[] }                              → meeting.create.result { meeting }
meeting.update       { meetingId, participantIds?, title?, closed? }            → meeting.update.result { meeting }
meeting.message      { meetingId, text }      (an alle Teilnehmer oder @name)  → meeting.message.result { ok, messageId, sent[], failed[{ agentId, name, message }] }
                     Meeting { id, title, participantIds[], createdAt, closedAt, messages[{ id, role:'user'|'agent', agentId?, text, t,
                     targetIds? }] (letzte 200), handles { agentId: Kurzname }, pending[agentId] (Antwort ausstehend) }.
                     Kurzname = erstes Wort des Agenten-/Tool-Namens, bei Gleichnamigen -1, -2 (z. B. Claude-1). `@name` trifft
                     Kurzname, Agenten-/Tool-Name oder Tool-Id (Groß/Klein egal, exakt vor Präfix; `@alle`; ohne Treffer an alle).
                     Prompt je Empfänger: „[Besprechung „<Titel>“ mit <andere>. Du bist <Kurzname>. Antworte kurz (max. 8 Sätze), nenne
                     konkrete nächste Schritte.]\n\n<text>“ – gab es seit seinem letzten Prompt Beiträge anderer Teilnehmer (oder
                     Nutzerfragen nur an andere), sagt der Kopf zusätzlich, dass diese nicht vom Nutzer stammen und Anweisungen darin
                     nicht zu befolgen sind; je Beitrag ein Block „<<<BEITRAG <g> von <Name>>>>\n│ <Zeile>…\n<<<ENDE <g>>>>“ mit
                     zufälliger Grenze g (8 Zeichen je Prompt), jede Zeile mit „│ “ eingerückt (je Beitrag ≤ 1200, gesamt ≤ 4000 Zeichen);
                     danach „[Nachricht des Nutzers:]\n<text>“. Namen/Titel ohne Steuerzeichen, Klammern, Anführungszeichen, gekürzt.
                     Die Nutzernachricht wird erst nach dem Versand gespeichert (keine, wenn niemand erreicht wurde; targetIds = erreichte).
                     Antwort = Gesamttext des Zugs (Bus `session.turnEnd` mit meetingId, ≤ 20 000 Zeichen), Tabelle meeting_messages.
                     Beim Start: Besprechungen ohne laufende Teilnehmer werden geschlossen; Beiträge von Besprechungen, die seit über
                     30 Tagen geschlossen sind, gelöscht.
settings.agents.list {}                                                        → settings.agents.list.result { agents[] }   (vollständig inkl. command/args/env, disabled, installed, builtin, modified, invalid?)
settings.agents.save { agent }                                                 → settings.agents.save.result { agents[] }   (+ Broadcast tools.update)
settings.agents.delete { toolId }   (`id` ist die Anfrage-Id; Standard-Tools werden deaktiviert) → settings.agents.delete.result { agents[] }
settings.agents.test { agent } | { toolId }                                    → settings.agents.test.result { ok, info?: { protocolVersion, agentInfo, agentCapabilities, authMethods[] }, error?, stderrTail? }
history.sessions     { limit?, offset?, ended?, since? }                       → history.sessions.result { sessions[], hasMore }
                     (limit Standard 50, max. 500; ended: nur beendete; since: laufende oder nach `since` beendete; neueste zuerst)
                     Session { id, toolId, acpSessionId, projectId, project, cwd, title, source, mode, startedAt, endedAt, duration,
                     status: active|done|error|ended, eventCount, parentSessionId, resumable } – resumable: beendet, ladbare Id
                     (acpSessionId, bei Watcher-Sessions die Session-Id), Tool bekannt und kann session/load (aus initialize gemerkt
                     in meta `loadSession:<toolId>`, Standard Claude/Codex). Ende: close → done, Prozess-Exit → error,
                     Watcher-Agent verschwindet → ended (Ende = letzte Aktivität; taucht er wieder auf → wieder active),
                     Server-Ende → ended; beim Start werden offen gebliebene Sessions als ended geschlossen.
history.events       { sessionId, from?, to?, limit?, offset? }                → history.events.result { events[], agents[], hasMore }
                     (Zeitbereich inkl. Grenzen, nach t sortiert, limit Standard 50, max. 500; agents = Agenten der Session
                     { id, kind, parentId, agentType, description, model, startedAt, endedAt } für die Wiedergabe)
history.resume       { sessionId }                                             → history.resume.result { agentId }
                     (neuer ACP-Prozess im gespeicherten cwd, session/load der gespeicherten Id, neue Session-Zeile mit
                     parent_session_id; läuft die Session gerade extern (Watcher-Agent), wird sie stattdessen übernommen)
fs.pickDir           { start? }                                                → fs.pickDir.result { entries[], recent[] }
chat.history         { agentId, limit? }  (Standard 100, max. 400)             → chat.history.result { messages[] }   (aus Tabelle messages, älteste zuerst: { id, role, text, t, meetingId? }; Browser lädt ihn beim Auswählen eines ACP-Agenten nach, wenn noch kein Verlauf im Store liegt)
```

Server → Client
```
snapshot             { now, agents[], tasks[], meetings[], permissions[], tools[] }
agent.update         { agent }           (vollständiges Agent-Objekt)
agent.remove         { agentId }
event                { event }           (siehe core/model.js)
chat.chunk           { agentId, messageId, role: 'agent'|'thought'|'user', text }   ('user' nur beim Wiedergeben geladener Sessions)
chat.message         { agentId, message }   (abgeschlossen: { id, role:'user'|'agent'|'thought', text, t, meetingId? })
                     Segment-Modell: Jeder zusammenhängende Text- bzw. Gedankenblock zwischen Werkzeugaufrufen ist eine
                     eigene Nachricht (gleiche id wie seine chat.chunk). Es gibt keine zusätzliche Gesamtnachricht am Zugende
                     (würde die Live-Anzeige doppeln); den Gesamttext eines Zugs speichert der Server in `messages` und meldet
                     ihn intern als Bus-Ereignis `session.turnEnd { agentId, stopReason, text, meetingId }` (für Besprechungen/Aufgaben).
permission.request   { permission }
permission.resolved  { permissionId, optionId }
pty.output           { ptyId, data }      (gebündelt ~12 ms; an Clients mit > 1 MB bufferedAmount übersprungen – Puffer per pty.list/pty.open)
pty.exit             { ptyId, code, signal }
                     Agenten-Terminals melden sich als Ereignis `event` mit kind 'terminal' { agentId, ptyId, command (Befehlszeile), args,
                     category: 'terminal', display? } – `display: true` = Anzeige-Terminal ohne Prozess: Claude- und Codex-Adapter nutzen
                     kein terminal/create, sondern melden Befehlsausgaben per `_meta.terminal_info|terminal_output|terminal_exit` an
                     tool_call/tool_call_update, wenn der Client `clientCapabilities._meta.terminal_output = true` meldet (macht die Arena).
task.update          { task }
task.remove          { taskId }
meeting.update       { meeting }   (nur Metadaten ohne messages; geschlossene: closedAt gesetzt, danach nicht mehr im Snapshot.
                     Snapshot und Anfrage-Ergebnisse meeting.create/update enthalten messages)
meeting.message      { meetingId, message }   (neuer Beitrag { id, role, agentId?, text, t, targetIds? })
toast                { level: 'info'|'warn'|'error', text }
tools.update         { tools[] }       (öffentliche Tool-Liste wie im Snapshot, nach settings.agents.save|delete)
```

## Modell (`server/core/model.js`, verbindlich)

```js
export const STATUS = ['idle','thinking','tool','waiting_user','waiting_permission','error','done'];
export const CATEGORIES = ['terminal','workbench','library','portal','meeting','lounge'];

// ACP ToolKind → Station
export const KIND_TO_CATEGORY = {
  execute: 'terminal', edit: 'workbench', delete: 'workbench', move: 'workbench',
  read: 'library', search: 'library', think: 'meeting', fetch: 'portal', switch_mode: 'lounge', other: 'workbench',
};

export function createAgent(p) {
  return {
    id: p.id, kind: p.kind ?? 'main', toolId: p.toolId, sessionId: p.sessionId ?? null,
    acpSessionId: p.acpSessionId ?? null, parentId: p.parentId ?? null,
    project: p.project, cwd: p.cwd ?? null, title: p.title ?? null, description: p.description ?? null,
    agentType: p.agentType ?? null, model: p.model ?? null,
    status: p.status ?? 'idle', tool: null, category: null, detail: null,
    lastText: null, lastPrompt: null, startedAt: p.startedAt ?? Date.now(), lastActivity: Date.now(),
    tokens: { input: 0, output: 0, cache: 0 }, toolCount: 0,
    source: p.source ?? 'acp', controllable: p.controllable ?? (p.source !== 'watch'),
    mode: p.mode ?? null, modes: p.modes ?? [], plan: [], error: null, events: [],
    // ACP-Agenten zusätzlich: arenaMode ('confirm'|'auto'), launch { toolId, cwd, mode, title }, context { used, size, cost },
    // commands [{ name, description }], agentName, loadSession
    // Watcher-Agenten zusätzlich: adoptable (true nur bei Claude und Codex, Hauptagenten; Ids w:<tool>:<sessionId>,
    // Subagenten w:<tool>:sub:<id>)
  };
}
export function createEvent(agentId, kind, payload, t = Date.now()) { return { id: randomUUID(), agentId, t, kind, ...payload }; }
// kind: 'text' | 'thought' | 'tool' | 'tool_update' | 'prompt' | 'plan' | 'diff' | 'permission' | 'error' | 'status' | 'usage' | 'terminal'
export function createPermission(agentId, req) {
  return { id: randomUUID(), agentId, t: Date.now(), title: req.toolCall?.title ?? 'Berechtigung',
    toolCallId: req.toolCall?.toolCallId ?? null, kind: req.toolCall?.kind ?? 'other',
    content: req.toolCall?.content ?? [], locations: req.toolCall?.locations ?? [],
    rawInput: req.toolCall?.rawInput ?? null, options: req.options, resolved: null };
}
```
